# Competition Demo Narrative

This document defines the live demo flow, talking points, and required
disclosures for the CrawlerNest Competition Track presentation. It describes
the 2026-09-04 snapshot: QS 9,530 source ranks, THE 1,637, and ARWU 838.
These are source coverage counts, not a claim that every source covers every
university.

---

## The Problem

University rankings are opaque. A student or advisor looking at a ranking sees
a number — but not why it is that number, which sources contributed, how much
those sources agree, or how confident the aggregated rank is.

This opacity matters because:
- Different ranking bodies (QS, THE, ARWU) often disagree significantly
- A university ranked 50 by one source and 150 by another is in an uncertain
  position — but that uncertainty is invisible in a single published number
- Historical rank movement requires access to multiple years of data from
  multiple sources, which is not typically surfaced in a usable form

---

## What CrawlerNest Solves

CrawlerNest makes university ranking data transparent and traceable:

1. **Multi-source aggregation with explainability.** A single aggregated rank
   is computed from QS, THE, and ARWU using a documented, deterministic formula.
   Every rank can be unpacked to show source contributions, normalized scores,
   weights, and confidence level.

2. **Source disagreement as signal.** When sources disagree, that disagreement
   is surfaced — not hidden. The analytics surface shows which universities
   have the largest cross-source rank spread and why.

3. **Honest data posture.** The platform discloses what it does not have:
  snapshot age, partial source coverage, entity-resolution limits, and missing
  values are labeled as such at every surface — API, frontend, and demo.

## Demo Flow

### Step 1: Open the Rankings Page

Show the global rankings page at `http://localhost:3000/`. Point out:
- 2026 snapshot coverage: QS 9,530, THE 1,637, and ARWU 838 source ranks
- The live `GET /api/v1/rankings?page=1&pageSize=5` response reports
  `totalCount: 2098`; this is the current canonical ranking universe, not the
  sum of source-row counts
- Explain that these counts are partial source coverage after entity resolution;
  they are not three complete, identical universes
- Filter by country, region, year
- The aggregated rank is computed, not scraped

### Step 2: Explain a Specific University

Click on a top university. Show the source comparison:
- Navigate to the university detail or use `GET /api/v1/universities/{id}/source-comparison`
- Demonstrate: "This rank is not just a number — it's derived from X sources.
  Here is what each source says, how their scores were normalized, and how much
  they agree."

### Step 3: Generate Recommendations and Explain Them

Navigate to `/recommendations`. Enter a target rank, IELTS score, and country. Walk through:

**Result cards:**
- "Each card shows a fit score derived from four dimensions: ranking fit, risk alignment,
  language fit, and data confidence. None of these are generated by AI — they are
  computed from stored data. Where a model estimate is shown, the response keeps
  `isEstimated` so the estimate cannot be mistaken for an observed source value."

**"Why this recommendation?" panel:**
- Click "Why this recommendation?" on any card. Show the expandable panel:
  - Reasons: "These come directly from the scoring logic — stored values and their
    arithmetic relationships to your input."
  - Warnings: "These are honest signals about data gaps. We do not suppress warnings
    to make a result look cleaner."
  - Source Coverage: "QS, THE, and ARWU are ingested for 2026, but coverage is
    partial. The confidence score reflects how many matched sources support this
    university — it is not inflated."
  - Data Caveats: "These caveats are present on every recommendation result.
    They are not optional disclosures."

**Evidence endpoint:**
- The panel fetches from `GET /api/v1/recommendations/explain?canonicalUniversityId=N`.
  This is a readonly endpoint that reads stored data without recalculating scores.
  "The explanation does not run the algorithm twice. It reads the same stored values
  the algorithm used, and surfaces them for human inspection."

**What the platform does NOT claim:**
- "This is not a black-box confidence score. You can see exactly where it comes from."
- "The recommendation order is not changed by the explanation layer."

### Step 4: Open the Analytics Page

Navigate to `/analytics`. Walk through:

**Ranking Trends:**
- "We can see how universities have moved year over year [IF multi-year data
  available]. Where only one year of data exists, we show that honestly —
  we do not extrapolate or project."

**Source Disagreement:**
- "These are the universities where the matched QS, THE, and ARWU ranks disagree
  most. A large rank spread is meaningful information — it tells us that
  confidence in the aggregated rank is lower."

**Source Coverage:**
- "This is a single 2026 snapshot. QS has 9,530 source ranks, THE 1,637, and
  ARWU 838. Coverage is partial because source tables and entity resolution do
  not produce identical universes."

**Analytics Caveats:**
- Read the caveats section directly to the audience. Do not skip it.
- "We show you exactly what limitations this data has. That is a feature,
  not a weakness."

### Step 4: Show the Diagnostics Layer

Navigate to `/system-status` or `/data-quality`. Point out:
- Data freshness state and last ingestion timestamp
- Source availability status
- Aggregation run history

"You can see exactly when the data was last updated and what the operational
state of the pipeline is. This is operational credibility — we do not hide
the infrastructure behind the numbers."

## Evidence-Backed Recommendations

CrawlerNest Phase 2 adds recommendation explanation as a first-class feature.
The explanation is not generated text — it is derived from stored evidence.

### Why Explainability Matters

A recommendation without an explanation is a black box. The user cannot know:
- Whether the rank used is from one source or three
- Whether IELTS data was available or assumed
- Whether confidence is high because the data supports it, or because it was defaulted
- What the actual IELTS requirement was, vs. the user's score

An explainable recommendation answers all of these from stored data.

### What the Explain Layer Does

Given a `canonicalUniversityId` (and optionally: `ieltsScore`, `targetRank`,
`country`, `subjectKey`), the explain endpoint returns:

| Evidence type | Source |
|---|---|
| Ranking evidence | `analytics.aggregated_rankings` — display rank, year, composite score |
| Source coverage | `source_ranks_json` — which of QS/THE/ARWU have rows |
| IELTS evidence | `warehouse.admission_requirements` — stored ielts_min + margin from user input |
| Country evidence | `warehouse.canonical_university` — stored country vs. user preference |
| Subject evidence | `warehouse.subject_ranking_record` — QS subject rank if available |
| Confidence evidence | Derived from completeness + source agreement (no hidden adjustment) |
| Caveats | Always present: snapshot age, partial THE/ARWU coverage, entity-resolution limits |

### What the Explain Layer Does NOT Do

- Does not re-run the recommendation scoring algorithm
- Does not change the recommendation order
- Does not generate text via LLM
- Does not inflate confidence beyond what the matched source data supports
- Does not suppress caveats or turn an unmatched source row into a source claim

### Why This Is Not Black-Box AI

The confidence score on each recommendation card is computed from:
1. A completeness component: does the record have a display_rank, ielts_min, and coverage_ratio?
2. A source agreement component: how many sources contributed, and how far apart are they?

Both inputs are stored in the database. Both outputs are derivable by inspection.
The formula is documented in `docs/RECOMMENDATION_EVIDENCE_MODEL.md`.

## Key Talking Points

- "Every rank is explainable. We can show you the formula, the sources, and
  the weights for any university in the system."

- "We surface disagreement. When QS says 50 and THE says 150, we show both
  numbers and tell you the spread is 100. That uncertainty is real information."

- "We are honest about what the snapshot contains. THE and ARWU are present,
  but partial. We show the coverage counts and do not pretend the three sources
  form a complete identical universe."

- "This is not AI-generated ranking synthesis. The formula is deterministic,
  version-tracked, and public. You can reproduce any output given the same
  source data."

- "The confidence level is derived from source coverage — not asserted. One
  source = low confidence. Three sources = high confidence. The system tells
  you which is which."

## What NOT to Claim

These claims would be dishonest at RC-1. Do not make them.

| Claim | Why Not |
| --- | --- |
| "Data is fully up to date." | This is a point-in-time 2026 snapshot, not a real-time feed. |
| "We cover every university in all major ranking sources." | THE and ARWU coverage is partial and entity matching can leave a source rank missing. |
| "AI-powered recommendations." | The recommendation engine is deterministic; no ML model is used. |
| "Predictive ranking forecasting." | No historical depth for trend prediction at RC-1. |
| "Real-time data." | Batch ingestion; no streaming pipeline. |
| "Subject rankings are comprehensive." | Subject data is incomplete at RC-1. |
| "Complete multi-source agreement for every university." | Agreement is shown only where matched source ranks exist; coverage is partial. |

---

## What Is Intentionally Limited at RC-1

These are not failures — they are scoped limitations that the platform
discloses honestly.

| Limitation | What Is Available Instead |
| --- | --- |
| Partial THE coverage | 1,637 THE source ranks in the 2026 snapshot; missing values remain disclosed |
| Partial ARWU coverage | 838 ARWU source ranks in the 2026 snapshot; missing values remain disclosed |
| Subject rankings incomplete | Global rankings complete and aggregated |
| Single-year aggregated data | No year-over-year claim is made from the current 2026 snapshot |
| Localhost-only deployment | Full operational stack, not a mock |
| Limited historical depth | Historical evidence preserved in snapshot system |

## Required Caveats During Demo

These must be stated verbally during any demo presentation. They are not optional.

1. "The ranking data is a point-in-time 2026 snapshot from the 2026-09-04
  ingest. It is not a real-time feed, and the exact freshness is shown by the
  API rather than implied."

2. "THE and ARWU are present with partial coverage: 1,637 THE and 838 ARWU
  source ranks. A missing rank may reflect snapshot coverage or entity
  resolution, so we do not claim that the source does not rank the university."

3. "Subject ranking coverage is incomplete and should be treated separately from
  the global 2026 source coverage."

4. "This is a localhost demonstration. The architecture is production-ready but
   the deployment is not production-scale."

See `docs/DEMO_HONESTY_GUIDELINES.md` for acceptable and unacceptable phrasing.
