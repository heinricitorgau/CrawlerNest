# CrawlerNest v0.3 Roadmap

## v0.2 Baseline

The `v0.2-2026-snapshot` release freezes a reproducible 2026 data baseline:

- QS 9,530, THE 1,637, and ARWU 838 source records.
- 10,125 aggregated ranking rows across global, region, regional, special, and
  subject scopes.
- Agent context locked to dataset year 2026, with evidence-first generation and
  no invented rows for unsupported years.
- ML estimates exposed through `analytics.v_ml_predictions_latest` while
  preserving `isEstimated`, support status, and uncertainty caveats.
- Entity resolution and source provenance retained in the PostgreSQL snapshot.

## v0.3 Priorities

### 1. Explicit Unsupported-Year Responses

The current Agent task path returns an empty result for a 2025 request rather
than a fabricated result, but the outer response can still be `success`. Add a
shared dataset-year guard at the API boundary that returns a stable warning or
rejection payload for every unsupported year, including the supported year and
the available-year list. Keep the existing no-hallucination behavior as a test
invariant.

### 2. Configured Web Generation Provider

Define the production provider contract, secrets/configuration boundary,
timeouts, streaming behavior, and fallback policy. Add an SSE path only after
the provider response has passed the existing provenance and caveat
verification. A provider must never become part of the ranking read path or
gain database write access.

### 3. Multi-Year Data Preparation

Prepare schema and aggregation contracts for historical years before ingesting
2025 or earlier data. Preserve `(canonical_university_id, ranking_year,
universe_type, universe_key, aggregation_run_id)` identity, then add explicit
delta semantics for missing years, source changes, and entity remaps. Trend
endpoints should distinguish observed deltas from unavailable history.

### 4. Release Verification as a Reusable Contract

Keep `scripts/restore_release_snapshot.sh` as the local/CI source of truth for
restoring a frozen database. Extend it with API smoke checks when a service is
available, and publish a new snapshot manifest for every release rather than
overwriting the v0.2 artifact.

## Guardrails

- Never describe partial THE/ARWU coverage as complete coverage.
- Never surface an estimate without `isEstimated` and support provenance.
- Never infer a year-over-year trend from the single-year v0.2 snapshot.
- Never let an LLM provider mutate warehouse or analytics data.
