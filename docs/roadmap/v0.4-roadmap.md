is the reproducible baseline. Every count below is in its `manifest.json`, read back from a restored copy:

- THE and ARWU 2015–2026; QS 2016, 2018–2020 and 2022–2026 (the archived editions with their own caveat).
- 44,510 source ranks, 27,409 aggregated rows, 4,059 canonical universities.
- US federal data (272 institutions, 7,870 figures) and 3,441 Wikipedia introductions.
- The October 2026 entity repairs (false merges split, 112 duplicate records merged).
- No user data in the dump. The v0.2 dump does hold two accounts. Its manifest says so; see "Open decisions".

## v0.4 priorities

### 1. Data reliability (first)

- **Classify every failure by source: THE and ARWU done.** Blocked, layout-changed, empty-table and HTTP-error
  failures now have their own classifications, and `test_source_failure_fixtures` pins each through the real
  crawler with no network. THE and ARWU now raise typed failures. QS's universe runs still classify
  by string. Give QS the same exception vocabulary, and have `scheduled_refresh` report per source and per
  classification over time, so a source that degrades slowly is visible before it fails.
- **Failure fixtures: started** (`crawlernest-tests/fixtures/source_failures/`, THE and ARWU). Still to do: QS.
  Record one captured response per known failure as a fixture: truncated ARWU payload, empty
  THE table, QS blank country, network timeout. Each must produce its classification with no network. Today only the
  ARWU truncation has one.
- **QS 2015 / 2021 / 2017.** Waiting on the decisions below. Once they are made, ingesting is a data migration:
  change `DATASET_COVERAGE`, rerun the entity checks (`split_false_entity_merges.py verify`, the Wikipedia
  `shared_with` check), then cut a release.

### 2. Before any public deployment

The gaps that block public exposure are closed. What remains:

- **A reverse proxy in front of Next.js: done.** `deploy/nginx/crawlernest.conf.example` replaces
  `X-Forwarded-For` with the address nginx saw, and `WEB_BIND=127.0.0.1` keeps the web container off the network.
- **A shared rate-limit store** if more than one API instance runs. Limits are counted per process today.
- **Backup and restore drill: done.** `./scripts/run_backup_restore_drill.sh --execute` (or `release_snapshot.py
  drill`) restores a backup into a scratch database and compares every table with live. A weekly user timer
  (`deploy/scheduler/crawlernest-backup-drill.timer`, installed by `install_scheduler.sh`) runs it and keeps the
  newest four of its own dumps.

### 3. Multi-year product surface

- The rank history is on the university page. Next, bring it to **compare** (two to four universities on one
  edition axis, per source, never a composite across editions) and to the agent's tools. Use the same statuses, so
  the agent can say "no QS 2017 edition is held" instead of guessing.
- **Movement lists:** the largest per-source movers between two adjacent held editions. Exact ranks only; banded
  ranks report an interval. `RANK_CHANGE_CAVEAT` already covers the wording.

### 4. ML research loop

- **Plug `CallableProposer` into the configured provider** (`agentModelProvider`). It is limited to the
  whitelisted spec space; a proposal outside that space is rejected and logged, never run.
- **Run the same loop on the disagreement model** (1,483 rows). It needs its own spec space and its own search and
  holdout split.
- **Holdout discipline.** Count holdout reads across runs, not only within one, and refuse a report once the
  holdout has been read more than a configured number of times. Ship a fresh split with the next QS edition.

### 5. Official data beyond the US

- **UK HESA / Discover Uni**, matched by identifier only (UKPRN through Wikidata P4971), with the same rules as the
  US data: not a ranking source, every value with its own period and status, and filters only.

### 6. Operations

- **Separate fast CI from warehouse validation.** Fixture tests run on every push. The warehouse drift gate and
  the database-backed checks run nightly against a restored release (now possible, since a release is a
  self-checking artifact), not only on the maintainer's machine.

## Guardrails (unchanged)

- Never describe partial coverage as complete; a missing rank is our gap, never a source declining to rank.
- Never surface an estimate without `isEstimated`.
- Never compare composite ranks across editions.
- Never let an LLM provider mutate warehouse or analytics data.
- US and other official figures never enter scoring, coverage or confidence.
