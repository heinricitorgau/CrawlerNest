## v0.4 priorities

### 1. Data reliability (first)

- **Classify every failure by source: done.** THE and ARWU raise typed failures (`blocked`, `layout_changed`,
  `empty_table`, `http_error`, ...). QS keeps its own codes (`upstream_blocked`, `resolve_not_found`, ...) and
  reaches the scheduled refresh as a `SourceFailure` carrying them, not as a bare `RuntimeError`. Every
  `run_status.json` and refresh outcome carries a cross-source `failure_family` (`sources/base.py:FAILURE_FAMILIES`).
  `scheduled_refresh_history.json` covers the last 12 refreshes per source: failures by family, consecutive
  failures, and rows per successful run. It warns on two failures in a row, on a drop of more than 2% since the
  previous success, and on three successive drops.
- **Failure fixtures: done for THE and ARWU** (`crawlernest-tests/fixtures/source_failures/`,
  `test_source_failure_fixtures`). QS's response classifier is covered by `test_fetcher` and `test_probe_qs_block`.
  Add a fixture whenever a source fails in a new way.
- **QS 2015 / 2021 / 2016 -> 2017: decided and done (2026-11-11).** 2015 and 2021 are not ingested (parked under
  `_not_ingested` in the manifest). QS's September 2016 table is relabelled 2017, the title QS gives it today: ingested
  as 2017, the identical 2016 rows retired, 2016 re-aggregated, exports and the MATLAB forecast re-run, and a release
  cut from the result (`v0.3.1-qs-2017-relabel`). QS now lacks 2015, 2016 and 2021.

### 2. Before any public deployment

The gaps that block public exposure are closed. What remains:

- **A reverse proxy in front of Next.js: done.** `deploy/nginx/crawlernest.conf.example` replaces
  `X-Forwarded-For` with the address nginx saw, and `WEB_BIND=127.0.0.1` keeps the web container off the network.
- **A shared rate-limit store** if more than one API instance runs. Limits are counted per process today.
- **Backup and restore drill: done.** `./scripts/run_backup_restore_drill.sh --execute` (or `release_snapshot.py
  drill`) restores a backup into a scratch database and compares every table with live. A weekly user timer
  (`deploy/scheduler/crawlernest-backup-drill.timer`, installed by `install_scheduler.sh`) runs it and keeps the
  newest four of its own dumps.

### 3. Multi-year product surface

- **Rank history: done** on the university page, the compare page (one chart per source, one line per
  university) and in the agent's university lookups (`core/services/rank_history.py`, identical to the API).
- **Movement lists: done.** `GET /api/v1/analytics/source-movers` and "Largest Movers by Source" on /analytics.
  They list exact movements only, between an edition and the held edition before it; banded and withheld
  movements are counted, and a missing edition (QS 2016) is withheld, never bridged.

### 4. ML research loop

- **A model as the proposer: done.** `loop.py --proposer llm` uses the agent's configured provider through
  `GuardedProposer`. Out-of-space proposals, repeats, prose and failed calls are refused and logged, never run, and
  the rule proposes that step instead.
- **Holdout discipline: done.** `holdout_ledger.json` counts reads per snapshot and split across runs; past the
  limit (default 3) the report withholds the holdout.
- **The disagreement model: done.** `ranking_ml/research/disagreement.py` runs the same loop through
  `SearchSpace` (10 valid specs, PR-AUC on a search split, threshold from the search rows). Random forest led the
  search but only narrowly the holdout, so the committed model is unchanged (model card, 2026-11-11).

### 5. Official data beyond the US

- **UK HESA / Discover Uni: not now (decided 2026-11-12).** Checked first: matching would work by identifier
  (Wikidata P4971 is the UKPRN), but the dataset's licence could not be confirmed (HESA's page for it refuses
  automated reads and, from a browser, no longer exists), and Discover Uni is mostly course-level, unlike the
  institution-level US figures. If it is taken up again: confirm the licence from HESA or OfS first, then decide
  between an institution-level subset and course-level data, with the US rules (not a ranking source, a period and
  status per value, filters only).

### 6. Operations

- **Fast CI and warehouse validation are separate: done.** Fixture tests run on every push; `warehouse-validation.yml`
  restores the newest release nightly and runs the drift gate and the database-backed suite against real data with
  `CRAWLERNEST_REQUIRE_WAREHOUSE=1`. Rehearsed locally on a scratch restore of v0.3: manifest, drift and all 1,205
  tests pass.

## Decisions taken (2026-11-11)

1. **The v0.2 dump in git history:** rewrite history so no commit carries its user rows.
2. **QS 2015 and 2021:** not ingested.
3. **QS 2016 label:** relabelled to 2017, following QS's current title.

## Guardrails (unchanged)

- Never describe partial coverage as complete; a missing rank is our gap, never a source declining to rank.
- Never surface an estimate without `isEstimated`.
- Never compare composite ranks across editions.
- Never let an LLM provider mutate warehouse or analytics data.
- US and other official figures never enter scoring, coverage or confidence.
