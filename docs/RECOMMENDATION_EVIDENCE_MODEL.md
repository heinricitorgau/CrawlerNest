# Recommendation Evidence Model

CrawlerNest Phase 2 — Competition Track

---

## Purpose

This document defines the evidence types used to explain recommendation results.
The goal is to make every recommendation traceable to stored data — not to a black-box
scoring formula or AI-generated inference.

All evidence is derived from:
1. **Stored data** — rows already in the database, unchanged by the explain request
2. **Derived metadata** — simple arithmetic on stored values (margins, ratios, confidence)
3. **User input** — the request parameters supplied by the user (IELTS, target rank, country)

No explanation is invented, hallucinated, or generated by a language model.

---

## Evidence Types

### 1. Ranking Evidence

**Source:** `analytics.aggregated_rankings` (most recent finished run, global scope)

| Field | Source | Type |
|-------|--------|------|
| `display_rank` | stored | Aggregated rank from latest run |
| `ranking_year` | stored | Year the aggregation covers |
| `composite_score` | stored | Aggregated composite score |
| `coverage_ratio` | stored | Fraction of sources that contributed |
| `aggregation_method_version` | stored | Which aggregation formula was used |
| `source_ranks_json` | stored | Per-source ranks (QS, THE, ARWU) |
| `source_count` | derived | Count of non-null source ranks |

Caveats always present:
- QS ranking data was last ingested at RC-1 packaging
- THE (Times Higher Education) data is not available at RC-1
- ARWU data is not available at RC-1

---

### 2. IELTS Evidence

**Source:** `warehouse.admission_requirements` joined via `warehouse.canonical_university_link`

| Field | Source | Type |
|-------|--------|------|
| `ielts_min` | stored | Minimum IELTS band required |
| `ielts_provided` | user input | IELTS score from request |
| `ielts_margin` | derived | `ielts_provided - ielts_min` |
| `ielts_fit` | derived | `meets` / `shortfall` / `no_data` |

Caveats:
- IELTS requirements may not be current; admission data is scraped, not live
- When `ielts_min` is null, no language requirement was found in stored data

---

### 3. Country Evidence

**Source:** `warehouse.canonical_university` joined to `warehouse.countries`

| Field | Source | Type |
|-------|--------|------|
| `university_country` | stored | Country where the university is located |
| `preferred_country` | user input | Country preference from request |
| `country_match` | derived | `exact_match` / `mismatch` / `no_preference` |

---

### 4. Subject Evidence

**Source:** `warehouse.subject_ranking_record` + `warehouse.ranking_subject` + `warehouse.ranking_source`

Only present when `subjectKey` is supplied in the request.

| Field | Source | Type |
|-------|--------|------|
| `subject_key` | user input | Subject identifier |
| `subject_name` | stored | Human-readable subject name |
| `rank_position` | stored | Numeric rank in subject |
| `rank_display` | stored | Display string (e.g. "51-100") |
| `score` | stored | Subject score (if available) |
| `source_code` | stored | Which source provided the subject rank |
| `has_data` | derived | Whether a subject row was found |

Caveats:
- Subject ranking rows are QS-only at RC-1
- Subject rows are sparse; many universities have no subject entry

---

### 5. Source Coverage Evidence

**Source:** `source_ranks_json` column of `analytics.aggregated_rankings`

| Field | Source | Type |
|-------|--------|------|
| `qs_rank` | stored | QS rank, or null |
| `the_rank` | stored | THE rank, or null |
| `arwu_rank` | stored | ARWU rank, or null |
| `source_count` | derived | Count of non-null source ranks |
| `coverage_label` | derived | `single_source` / `multi_source` / `no_source` |

RC-1 note: all universities have `source_count = 1` (QS only).

---

### 6. Confidence Evidence

**Source:** Derived from stored values — no separate table

| Field | Source | Type |
|-------|--------|------|
| `confidence_score` | derived | 0–100 numeric confidence |
| `confidence_label` | derived | `high` / `medium` / `low` |
| `confidence_reason` | derived | Human-readable explanation |

Confidence derivation (read-only, never mutated):
- **Completeness component** (65%): whether `display_rank`, `ielts_min`, and `coverage_ratio` are present
- **Source agreement component** (35%): spread across QS/THE/ARWU ranks; single source = 68/100

Thresholds:
- `high`: confidence_score ≥ 80
- `medium`: confidence_score ≥ 60
- `low`: confidence_score < 60

---

### 7. Caveat Evidence

Caveats are always disclosed in every explain response. They are not optional.

**Required caveats at RC-1:**

| Caveat | Trigger |
|--------|---------|
| QS data is stale (last ingested at RC-1) | Always |
| THE data unavailable | Always |
| ARWU data unavailable | Always |
| IELTS requirement is missing or incomplete | When `ielts_min` is null |
| Subject data not found for this university | When `subjectKey` supplied but no row found |
| Single-source ranking only | When `source_count = 1` |

---

## What the Evidence Layer Does NOT Do

- Does not re-run the recommendation scoring algorithm
- Does not change the existing recommendation order
- Does not synthesize explanations from a language model
- Does not invent confidence scores beyond what the data supports
- Does not claim multi-source agreement when only QS is available
- Does not suppress caveats to appear more confident

---

## Evidence vs. Scoring

The evidence layer and the scoring layer are separate:

| Layer | Purpose | Mutates data? |
|-------|---------|---------------|
| Scoring (`RecommendationService`) | Ranks and classifies candidates | No |
| Evidence (`RecommendationEvidenceService`) | Explains from stored data | No |

The explain endpoint (`GET /api/v1/recommendations/explain`) reads from the database
without calling any scoring method. It returns the same underlying data that informs
scoring, but packaged for human-readable explanation.

---

## API Contract

```
GET /api/v1/recommendations/explain
  ?canonicalUniversityId=<long>   (required)
  &ieltsScore=<double>            (optional)
  &targetRank=<int>               (optional)
  &country=<string>               (optional)
  &subjectKey=<string>            (optional)

Response: ApiResponse<Map> with:
  - university_identity
  - ranking_evidence
  - ielts_evidence
  - country_evidence
  - subject_evidence (if subjectKey provided)
  - source_coverage
  - confidence_evidence
  - caveats[]
  - data_freshness
  - evaluation_timestamp
```

404 if `canonicalUniversityId` not found in the database.
